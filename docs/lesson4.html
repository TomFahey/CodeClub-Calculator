🔁 Quick Recap from Session 3

At the end of Session 3 your handle_key used the factorial function to show a fun result when you pressed a digit. Here is what it looked like:

Today we replace this with the real handle_key. Here it is: 

def handle_key(key):
    global inputs, operator
    if key in number_keys:
        add_digit(key)
    elif key in operator_keys:
        press_operator(key)
    elif key == "=":
        press_equals()
    elif key == "C":
        press_clear()
    elif key == "DEL":
        press_delete()
    elif key == "+/-":
        press_negate()
    show_input(f"{inputs[0]} {operator} {inputs[1]}")

Notice the new line at the very bottom of handle_key: show_input(f"{inputs[0]} {operator} {inputs[1]}"). That runs after every key press, updating the top display line. You already learned about f-strings in Session 2 — the {inputs[0]}, {operator} and {inputs[1]} inside the curly brackets are filled in automatically with whatever those variables currently hold.

Phase 1 — add_digit(key): Building Up a Number

Indexing a List with a Variable
📬 Analogy: two mailboxes
Imagine a row of two mailboxes labelled 0 and 1. selected_input is the number painted on the door you are currently using. When selected_input is 0, you put letters in box 0. When it is 1, you put them in box 1. The same action — directed to different places. 
inputs = ["", ""]
selected_input = 0

inputs[selected_input] = "hello"   # same as inputs[0] = "hello"
show_result(inputs[0])             # shows: hello

selected_input = 1
inputs[selected_input] = "world"   # same as inputs[1] = "world"
show_result(inputs[1])             # shows: world
show_result(inputs[0])             # still shows: hello

You already know how to use a fixed number like inputs[0]. Now the index itself is a variable. The same code can work on different slots just by changing what selected_input holds.

selected_input as a Switch
🚃 Analogy: a railway track switch
When selected_input = 0 the track points to slot 0 (the first number). When selected_input = 1 the track points to slot 1 (the second number). The same add_digit code runs every time — but thanks to selected_input, it writes digits to different slots.

When does the switch flip? Only in press_operator — when you press +, −, x, or /.

The code

def add_digit(key):
    global inputs, selected_input
    if key == "." and "." in inputs[selected_input]:
        return
    else:
        inputs[selected_input] = inputs[selected_input] + key

Step by step:

  1. global inputs, selected_input — both are modified, so we declare them global to be safe.
  2. Decimal guard: if key == "." and "." in inputs[selected_input]: return — a number can only have one decimal point. If there is already one in the current slot, we return early (exit the function without doing anything).
  3. inputs[selected_input] = inputs[selected_input] + key — append the new character to whichever slot selected_input is pointing at. Just like the rick function from Session 3 that grew a string one piece at a time.
  4. No show_input here — handle_key will update the display after this function returns.

🔬 Try It

Run the program. Press digit keys 4, 2, 5. The input display at the top should show 425  . Press 7 — it should show 4257  .

🏆 Phase 1 Challenge

What does inputs[selected_input] equal when selected_input == 0 and the user has typed "42"? What about when selected_input == 1 and they have typed "5"?

💡 Answer

When selected_input == 0: inputs[selected_input] is the same as inputs[0], which equals "42".
When selected_input == 1: inputs[selected_input] is the same as inputs[1], which equals "5".
The expression is identical — only the value of selected_input changes which slot it accesses.

Phase 2 — press_operator(key): Switching Slots

The Save-Point
🎮 Analogy: a save-point in a video game
The moment you press an operator key, the calculator freezes the current state — like hitting Save in a game. It checks there is something to work with, remembers which operator you chose, and flips the switch so the next digits go into the second slot.

The code

def press_operator(key):
    global inputs, selected_input, operator, stored_answer
    if (selected_input == 0):
        if (inputs[0] == ""):
            if stored_answer is None:
                return
            else:
                inputs[0] = stored_answer
        operator = key
        selected_input = 1

Step by step:

  1. Only act if we are still on slot 0 — if (selected_input == 0). If the user already pressed an operator (we are on slot 1), pressing another one does nothing.
  2. Check there is something to work with — if (inputs[0] == ""): if no digits have been typed yet, check stored_answer. If there is no stored answer (is None), return early. If there is one (from a previous calculation), copy it into inputs[0] so we can chain calculations.
  3. operator = key — remember which symbol was pressed ("+", "-", "x", or "/").
  4. selected_input = 1 — flip the switch. From now on, add_digit writes into inputs[1].
  5. No show_input — handle_key handles the display.

Type 7 then +. The display should show 7 +   (operator visible, slot 1 empty). Type 3 — it should show 7 + 3.

Same pattern — check a value, do something different for each case, return the result. calculate is just the calculator version of the referee function.

# Session 4 — calculate
def calculate():
    first_number  = float(inputs[0])
    second_number = float(inputs[1])
    if operator == "+":
        result = first_number + second_number
    # ... etc
    return result
float() — Converting a String to a Number
🔢 Analogy: reading a number off a piece of paper
When you type digits on the keyboard they are stored as text — the string "42", not the number 42. To do arithmetic, Python needs an actual number. float("42") reads the string and hands back 42.0.

Try this in the shell to see the difference: 
print("42" + "5")                # "425"  — string concatenation!
print(float("42") + float("5"))  # 47.0   — number addition!

The code

def calculate():
    first_number  = float(inputs[0])
    second_number = float(inputs[1])
    if operator == "+":
        result = first_number + second_number
    elif operator == "-":
        result = first_number - second_number
    elif operator == "x":
        result = first_number * second_number
    elif operator == "/":
        if second_number == 0:
            return "Error"
        result = first_number / second_number
    else:
        result = second_number
    return result

Step by step:

  1. float(inputs[0]) and float(inputs[1]) — convert the typed text to real numbers. Note: calculate only reads inputs and operator, so no global declaration is needed!
  2. The if/elif chain — same pattern as rock_paper_scissors. Checks operator and runs the matching calculation.
  3. Division-by-zero guard — dividing by zero is impossible, even for computers. If someone types 5 / 0, we return the string "Error" instead of crashing. This is called a guard clause — an early return that stops a problem before it happens.
  4. The else branch — if somehow no operator was set, return second_number as a safe fallback.
  5. return result — hand the answer back to whoever called calculate().

Phase 4 — press_equals(): The Tournament Director

Remember tournament from Session 3?
tournament was the director — it called rock_paper_scissors (the referee).
press_equals is the director — it calls calculate (the maths engine).

press_equals does not do the arithmetic itself. It checks everything is ready, asks calculate for the answer, then handles the result — showing it, saving it, resetting the state.

Side by side:

def tournament(p1_moves, p2_moves):
    for i in range(len(p1_moves)):
        rock_paper_scissors(p1_moves[i], p2_moves[i])

# Session 4
def press_equals():
    ...
    answer = calculate()   # call the maths engine
    ...

The code

def press_equals():
    global inputs, selected_input, operator, stored_answer
    if (operator == "") or (inputs[0] == "") or (inputs[1] == ""):
        return
    answer = calculate()
    if answer == "Error":
        inputs[0] = ""
        inputs[1] = ""
        selected_input = 0
        operator  = ""
        show_result("Error!")
        return
    if answer == int(answer):
        answer = int(answer)
    inputs[0] = ""
    inputs[1] = ""
    selected_input = 0
    operator  = ""
    show_result(answer)
    stored_answer = str(answer)

Step by step:

  1. Guard clause — all three must be set: operator, inputs[0], and inputs[1]. If any are missing, return early without doing anything.
  2. Call the maths engine — answer = calculate(). The real arithmetic happens here.
  3. Handle errors — if calculate returned "Error" (divide by zero), clear everything and show "Error!" on screen, then return early.
  4. Strip the .0 — if answer == int(answer): answer = int(answer). Python gives 5.0 for 10 ÷ 2. If the decimal part is zero, convert to an integer so we display 5 not 5.0.
  5. Reset state — clear inputs[0], inputs[1], selected_input, and operator back to their starting values.
  6. Show the answer — show_result(answer).
  7. Save for chaining — stored_answer = str(answer). If the user immediately presses an operator after seeing the result, press_operator will find stored_answer and use it as the first number. We store it as a string because inputs[0] is always a string.

Phase 5 — The Finishing Touches

5a — press_clear(): The Reset Button

None — A Special Python Value
📭 Analogy: an empty letter box
None means “there is nothing here at all” — not 0 (which is still a number) and not "" (which is still a string). It is Python’s way of saying “this slot has not been filled in yet.”

We use it for stored_answer because until you have calculated something, there truly is no previous answer — not even zero. Pressing C also resets stored_answer back to None. 
def press_clear():
    global inputs, selected_input, operator, stored_answer
    inputs[0]      = ""
    inputs[1]      = ""
    selected_input = 0
    operator       = ""
    stored_answer  = None
    show_result("0")
  1. Every variable goes back to its starting value from the top of the file.
  2. stored_answer = None — not 0 or "". None means “there is no stored answer at all.”
  3. show_result("0") — show 0 in the result area, just like a real calculator after pressing C.
  4. We do not call show_input here — handle_key will do that via the f-string immediately after, and with all inputs cleared it will show just spaces, effectively clearing it.

5b — press_delete(): Slicing Off the Last Character

String Slicing — Cutting a String Apart
✂️ Analogy: cutting a strip of paper
Imagine a word written on a strip of paper. You can cut off a piece to get a shorter strip. You already know how to pick one character with a single index. Slicing uses a colon to get a range of characters. 
word = "hello"
print(word[0])    # "h"     — first character
print(word[4])    # "o"     — last character (index 4)

print(word[1:])   # "ello"  — everything from position 1 to the end
print(word[:-1])  # "hell"  — everything EXCEPT the last character
print(word[1:3])  # "el"    — positions 1 and 2 (stops before 3)

[:-1] means “give me everything up to, but not including, the very last character.” Negative indices count backwards from the end: word[-1] is the last character, word[-2] is the second-to-last, and so on. That is exactly what DEL needs: chop off the last digit. 

def press_delete():
    global inputs, selected_input, operator
    current_input = inputs[selected_input]
    if len(current_input) > 0:
        inputs[selected_input] = current_input[:-1]
    else:
        operator       = ""
        selected_input = 0
  1. current_input = inputs[selected_input] — a local “shortcut” variable so we do not have to write inputs[selected_input] repeatedly. This is a local variable — it only exists inside this function.
  2. If there are characters to delete: slice off the last one with [:-1]. Pressing DEL on "425" gives "42", again gives "4", again gives "".
  3. The else branch — if the slot is already empty, we go back a step: clear the operator and flip selected_input back to 0. This lets you undo pressing an operator by mistake!
  4. No show_input — handle_key handles it.

5c — press_negate(): Flipping the Sign

Checking and Modifying the First Character
➕➖ Analogy: a sign on a number
If the number is positive, stick a - on the front to make it negative. If it already starts with -, peel off that first character to make it positive again.

We use [0] to check the first character and [1:] to remove it — both techniques you have now seen! 
def press_negate():
    global inputs
    current_input = inputs[selected_input]
    if current_input == "" or current_input == "0":
        return
    if current_input[0] == "-":
        inputs[selected_input] = current_input[1:]
    else:
        inputs[selected_input] = "-" + current_input
  1. current_input = inputs[selected_input] — the same local alias trick as in press_delete.
  2. Guard clause: empty strings or "0" do not need negating — return early.
  3. current_input[0] == "-" — check the first character. If negative, use [1:] to strip the - from the front.
  4. If positive, prepend "-" with string concatenation.
  5. Important: we assign to inputs[selected_input], NOT to current_input. Changing the local alias would not update the list — we must assign back to the actual slot.

🔬 Try It

Type 42, press +/− — display shows -42. Press again — back to 42. Try after pressing an operator too: 5 + 3 +/− should show 5 + -3.

📚 What You Learned Today

Indexing with a variable
inputs[selected_input] — the same code can work on different slots depending on what selected_input holds.
selected_input as a switch
Starts at 0 (typing the first number), flips to 1 when an operator is pressed (typing the second number), resets to 0 after equals or clear.
stored_answer
Remembers the last result so you can chain calculations — press an operator immediately after seeing a result, and it uses that result as the first number.
Guard clauses
Return early to skip bad inputs without crashing. Used in press_operator, press_equals, and press_negate.
String slicing
[:-1] removes the last character; [1:] removes the first; [1:3] gives characters at positions 1 and 2. Negative indices count backwards from the end.
float()
Converts a typed string like "42" into the real number 42.0 so you can do arithmetic with it.
None
A special Python value meaning “nothing here yet” — different from 0 (a valid number) or "" (an empty string).
Centralised display
handle_key calls show_input once, at the very end, for every key press. Individual functions stay focused on their own job and do not touch the display.
