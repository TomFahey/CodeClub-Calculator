Phase 1 — add_digit(key): Building Up a Number

🎵 Remember rick(choice) from Session 3?

In Session 3 you wrote a function called rick(choice). Every time it ran, it added another chunk of a song lyric onto a variable called lyric. By the time you called it three times, lyric had grown from "never gonna " all the way to "never gonna give you up". 

def rick(choice):
    global lyric
    lyric = lyric + choice   # grow the string by one piece

add_digit works in exactly the same way — but instead of song lyrics it adds digits to current_input. Press 4, then 2, then ., then 5, and current_input grows one character at a time: 

""  →  "4"  →  "42"  →  "42."  →  "42.5"

Just like rick needed global lyric to change the variable that lives outside the function, add_digit needs global too — because it changes current_input.

🚦 New concept: a boolean flag

A flag is a variable that can only be True or False — like a traffic light that is either green or red. The variable start_new_number is the calculator’s green/red light. When it is True it means: “the next digit you type should start a brand-new number, not be added to the old one.”

When you press an operator key (like +) or the equals key, start_new_number is set to True — red light. As soon as you type the first digit of a new number, add_digit flips it back to False — green light.

The code

def add_digit(key):
    global current_input, start_new_number, expression_prefix

    if start_new_number:
        current_input    = ""
        start_new_number = False

    if key == "." and "." in current_input:
        return

    current_input = current_input + key
    show_input(expression_prefix + current_input)

Step by step

  1. global current_input, start_new_number, expression_prefix
    This function changes all three of those variables, so Python needs to be told they come from outside the function. (You only need global when you write to a variable, not when you just read it.)
  2. The red-light check
    If start_new_number is True, wipe current_input back to an empty string and flip the flag to False. This makes the next digit start fresh instead of joining the old number.
  3. The decimal-point guard
    if key == "." and "." in current_input: return
    A number can only have one decimal point. If someone presses . a second time, we do nothing — return exits the function early.
  4. Grow the string
    current_input = current_input + key — same trick as rick, adding one character to the end each time.
  5. Update the display
    show_input(expression_prefix + current_input) shows the full expression (for example "7 + 42") in the top area of the calculator. expression_prefix is set in Phase 2; for now it is an empty string, so the display just shows the digits you’ve typed.

🔌 Try It — typing digits

Run the program on your Tab5. Press 4, 2, 5. The display should show 425. Press 7 — it should grow to 4257. Press . twice — only one dot should appear.

Hint — the display isn’t updating?

Check that add_digit is defined before handle_key in your file. Also make sure your global line lists all three variables: global current_input, start_new_number, expression_prefix.

Phase 2 — press_operator(key): The Save Point

💾 Analogy: save points in a game

Imagine playing a platform game and reaching a checkpoint. The game takes a snapshot of everything — your score, your position, your lives — and stores it safely. If you fall off a ledge later, it reloads from that exact snapshot.

When you press + on the calculator, press_operator does the same thing: it saves the number you just typed into first_number, saves which operator you pressed into operator, and sets the start_new_number flag so the next digits you type start a fresh number.

The code

def press_operator(key):
    global first_number, operator, start_new_number, expression_prefix

    if current_input != "":
        first_number = float(current_input)

    operator          = key
    expression_prefix = current_input + " " + key + " "
    start_new_number  = True

    show_input(expression_prefix)

Step by step

  1. Save the first number
    if current_input != "": first_number = float(current_input)
    We convert the text on screen (e.g. "7") into a real number with float(). The if guard stops a crash if someone presses an operator before typing any digits.
  2. Remember the operator
    operator = key saves the key that was pressed — one of "+", "-", "x", or "/".
  3. Build the expression prefix
    expression_prefix = current_input + " " + key + " "
    If you typed 7 and pressed +, this becomes "7 + ". From now on every call to add_digit will show this prefix in front of whatever you are currently typing, so the display reads "7 + 3" as you type the second number.
  4. Set the traffic light to red
    start_new_number = True — the next digit typed will start a fresh number instead of continuing the old one.
  5. Update the display
    show_input(expression_prefix) shows e.g. "7 + ", ready for the second number to be typed.

🔌 Try It — typing an operator

Type 7 then +. The display should show 7 + (with a trailing space). Now type 3 — it should show 7 + 3. Type 2 — it should grow to 7 + 32.

Hint — the display shows the wrong thing after the operator?

Check that expression_prefix is in the global line of both press_operator (where it is written) and add_digit (where it is read). Both functions need to share the same variable.

Phase 3 — calculate(): The Maths Engine

✂ Remember rock_paper_scissors from Session 3?

In Session 3 you built rock_paper_scissors(hand1, hand2). It used a long if/elif/else chain to check what each player had thrown and then decide a winner. The calculate() function is built the exact same way: it checks which operator was saved and then runs the matching sum.

Session 3 — rock_paper_scissors

def rock_paper_scissors(hand1, hand2):
    if hand1 == hand2:
        show_result("Draw!")
    elif hand1 == rock and hand2 == scissors:
        show_result("Player 1 wins!")
    elif hand1 == paper and hand2 == rock:
        show_result("Player 1 wins!")
    elif hand1 == scissors and hand2 == paper:
        show_result("Player 1 wins!")
    else:
        show_result("Player 2 wins!")

Checks a value, does something different for each case.

Session 4 — calculate

def calculate():
    second_number = float(current_input)

    if operator == "+":
        result = first_number + second_number
    elif operator == "-":
        result = first_number - second_number
    elif operator == "x":
        result = first_number * second_number
    elif operator == "/":
        if second_number == 0:
            return "Error"
        result = first_number / second_number
    else:
        result = second_number

    return result

Checks a value, does something different for each case.

Can you see the pattern? Both functions use an if/elif/else chain to inspect a value and do something different for each possibility. Both also use return to hand back a result to whoever called them.

Step by step

  1. Read the second number
    second_number = float(current_input) — whatever the user typed last is still in current_input. We convert it from text to a real number with float().
  2. Check the operator and do the maths
    The if/elif chain inspects the operator variable saved in Phase 2 and runs the right calculation. The button label is "x" for multiplication, but Python’s multiply symbol is *, so we translate: result = first_number * second_number.
  3. Divide-by-zero guard 🛡
    if second_number == 0: return "Error"
    Dividing by zero is impossible — even computers cannot do it. If someone types 5 / 0 =, we return the special string "Error" instead of crashing. Returning early like this is called a guard clause.
  4. The else branch
    If somehow no operator was set, we return second_number on its own — a sensible fall-back that stops a crash.
  5. return result
    The function hands back the answer. Remember from Session 3: a function with return is like a machine that produces an output you can catch in a variable — answer = calculate().

    ...
    answer = calculate()
    ...

The director (press_equals) calls the maths engine (calculate) to do the arithmetic.

The full code

def press_equals():
    global current_input, first_number, operator, start_new_number

    if operator == "" or current_input == "":
        return

    answer = calculate()

    if answer == "Error":
        show_input("")
        show_result("Error!")
        current_input    = ""
        operator         = ""
        start_new_number = False
        return

    if answer == int(answer):
        answer = int(answer)

    show_input("")
    show_result(answer)

    current_input    = str(answer)
    first_number     = 0
    operator         = ""
    start_new_number = True

Step by step

  1. Guard clause
    if operator == "" or current_input == "": return
    If the user presses = without having typed an operator and a second number, we ignore the press. No crash, no weird result — just an early return.
  2. Call the maths engine
    answer = calculate() — this is the key line. We hand all the real arithmetic to calculate and catch whatever it returns in answer.
  3. Handle errors
    If calculate returned the string "Error" (because of a divide-by-zero), show "Error!" on screen, reset all the state variables, and return early so we skip the rest of the function.
  4. Remove the trailing .0
    if answer == int(answer): answer = int(answer)
    Python stores results like 10 ÷ 2 = 5.0. If the decimal part is zero (it is a whole number), we convert to an integer so the display shows 5, not 5.0.
  5. Show the result
    show_input("") clears the expression at the top; show_result(answer) shows the answer in the large result area.
  6. Reset state for the next sum
    The answer is stored back into current_input as a string, so you can immediately chain another operation (press +2= to add 2 to the result). operator is cleared and start_new_number is set to True so the next digits start a fresh number.

Phase 5 — The Finishing Touches

The calculator can now add, subtract, multiply, and divide. This phase adds the last three buttons: C (clear everything), DEL (remove one digit), and +/− (flip the sign).

5a — press_clear()

🔄 Analogy: pressing Reset in a game

When you press Reset on a game console the whole game goes back to the very beginning — score back to zero, lives back to three, position back to the start screen. Nothing from the last game is remembered. press_clear does exactly this for the calculator: every variable goes back to its original starting value. 

def press_clear():
    global current_input, first_number, operator, start_new_number, expression_prefix

    current_input     = ""
    first_number      = 0
    operator          = ""
    start_new_number  = False
    expression_prefix = ""

    show_input("")
    show_result("0")
  1. Every state variable is set back to the exact value it had at the top of the file when the program first started.
  2. show_input("") clears the top display area.
  3. show_result("0") shows 0 in the result area — just like a real calculator after you press C.

5b — press_delete(): Slicing Off the Last Character

✂ New concept: string slicing

Imagine a word written on a strip of paper. You can cut bits off it. In Python, slicing lets you take a portion of a string. You use a colon : inside the square brackets.

You already know how to pick one character using an index (from Session 2):

word = "hello"
print(word[0])    # "h"  — the first character

Slicing uses a colon to grab a range of characters:

word = "hello"
print(word[1:])   # "ello"  — everything from position 1 to the end
print(word[:-1])  # "hell"  — everything EXCEPT the last character

The [:-1] slice means “give me everything up to, but not including, the very last character.” That is exactly what DEL needs to do: chop off the last digit.

We also use len() to count how many characters are in a string:

print(len("hello"))   # 5
print(len(""))        # 0  — an empty string has length zero
def press_delete():
    global current_input

    if len(current_input) > 0:
        current_input = current_input[:-1]

    show_input(expression_prefix + current_input)
  1. if len(current_input) > 0
    Only try to delete if there is something there. If current_input is already empty, len returns 0, so we skip the slice and avoid an error.
  2. current_input = current_input[:-1]
    The [:-1] slice removes the last character. Pressing DEL on "425" gives "42"; pressing again gives "4"; pressing once more gives "".
  3. Update the display to show the shortened number.

5c — press_negate(): Flipping the Sign

➕➖ How to flip positive and negative

If the number on screen is positive (e.g. "42"), we stick a minus sign on the front to make it "-42". If it already starts with a minus sign, we peel off that first character to get back to "42".

We use indexing ([0]) to peek at the first character — exactly the same as you did in Session 2 — and slicing ([1:]) to remove it: 

text = "-42"
print(text[0])    # "-"   — the first character
print(text[1:])   # "42"  — everything after the first character
def press_negate():
    global current_input

    if current_input == "" or current_input == "0":
        return

    if current_input[0] == "-":
        current_input = current_input[1:]
    else:
        current_input = "-" + current_input

    show_input(expression_prefix + current_input)
  1. Guard clause
    If current_input is empty or just "0", do nothing. Negative zero does not mean anything useful, so we return early.
  2. Check the first character with [0]
    if current_input[0] == "-" — is there already a minus sign at the front?
  3. If yes — strip the minus with [1:]
    current_input = current_input[1:] gives everything after the first character, which removes the "-".
  4. If no — add a minus
    current_input = "-" + current_input sticks "-" on the very front.
  5. Update the display.

Test each new button:

  • Type 42, then press +/−. The display should show -42. Press +/− again — back to 42.
  • Do any calculation, then press C. Both display areas should clear and the result should show 0.
Hint — DEL seems to delete too many characters?

Check that expression_prefix is not listed on the global line of press_delete. That function only reads expression_prefix (in the last show_input call), so it does not need to declare it global.

Hint — +/− does not work after pressing =?

After =, the answer is stored back into current_input and start_new_number is True. Press +/− before typing a new digit and it will negate the answer. If you type a digit first, add_digit will have already wiped current_input clean.
