Phase 1 — What is a Function?

def — Writing Your Own Recipe
🍰 Analogy: a recipe book
Imagine you write a recipe for chocolate cake. You write it down once, give it a name, and from then on anyone who wants chocolate cake just says "make the chocolate cake recipe". They don't have to re-read all the steps — they just use the name.

In Python, def is how you write the recipe. Typing the function's name with brackets () is how you run it.

Here is the basic shape of a function in Python. Every single part matters, so let's look at each piece: 

def function_name(parameter1, parameter2):
    # everything indented by 4 spaces belongs to the function
    # do some work here
    return result
  • def — tells Python "I am writing a function now".
  • The name — you choose it; use lowercase letters and underscores.
  • Round brackets () — hold the parameters (the ingredients the function needs).
  • The colon : — marks the start of the recipe steps.
  • 4 spaces of indentation — every line that belongs to the function must be indented (shifted right) by 4 spaces. Python uses this to know where the function ends.
  • return — hands a result back to whoever called the function, like passing the finished cake through the serving hatch.

Example 1 — A function that displays something

Let's start simple. This function takes a word and a number, then shows the word that many times on screen. It doesn't need to return anything — it just does a job. 

def repeat_word(word, times):
    show_result(times * word)

repeat_word("hello ", 3)    # shows: hello hello hello
repeat_word("beep ", 5)     # shows: beep beep beep beep beep

Step by step: when Python reaches repeat_word("hello ", 3), it jumps inside the function. word gets the value "hello " and times gets the value 3. Then 3 * "hello " produces the string "hello hello hello ", which show_result puts on screen. Python then comes back out of the function and carries on with the next line.

Example 2 — A function that returns True or False

This function checks whether a number is even and returns an answer. Before we look at the code, here is a quick maths reminder:

% — The Remainder Operator (Modulo)
🍕 Analogy: sharing slices of pizza
If you have 10 slices and 3 friends, each friend gets 3 slices and you have 1 left over. 10 % 3 gives you that leftover: 1.

If a number is even, dividing it by 2 leaves no remainder — so num % 2 == 0 means "num is even". 
def is_even(num):
    if num % 2 == 0:
        return True
    else:
        return False

show_result(is_even(4))     # True
show_result(is_even(7))     # False

Notice: the if and else are indented 4 spaces (inside the function), and the return lines are indented 8 spaces (inside the if/else block). Python uses those indentation levels to know exactly what belongs where.

🔬 Try It

What does is_even(100) return? What about is_even(1)? Try a few numbers of your own.

💡 Hint

100 % 2 is 0, so is_even(100) returns True. 1 % 2 is 1 (not zero), so is_even(1) returns False.

Example 3 — A function that does arithmetic

Functions are great for maths that you want to repeat without retyping. This one converts a temperature from Celsius to Fahrenheit. 

def celsius_to_fahrenheit(temp):
    result = temp * 9 / 5 + 32
    return result

show_result(celsius_to_fahrenheit(0))     # 32.0  — freezing point
show_result(celsius_to_fahrenheit(100))   # 212.0 — boiling point

The function stores the answer in a local variable called result, then hands it back with return. show_result receives that value and displays it. (We'll learn much more about local variables in Phase 3.)

💡 Hint

Phase 2 — Functions that Make Decisions: Rock Paper Scissors

Functions become really powerful when they can look at their inputs and take different actions depending on what they find. We already saw a tiny bit of this with is_even — now let's build something bigger: a Rock Paper Scissors referee.

if / elif / else — Signposts at a Junction
🛣️ Analogy: signposts at a road junction
Imagine arriving at a crossroads with several signposts. You read the first one — if it matches where you're going, you take that road and ignore all the others. If not, you move on to the next sign. if is the first signpost. elif (short for "else if") is every sign after that. else is the last sign that says "take this road if none of the others matched". Python reads them top to bottom and stops as soon as it finds one that is true.

Setting up the hand values

Instead of typing the strings "rock", "paper", and "scissors" everywhere (and risking a typo), we give each hand a number: 

rock     = 0
paper    = 1
scissors = 2

Now whenever we want to say "rock", we just write the variable name rock. Python can compare numbers quickly with ==, and if we ever mistype the variable name Python will tell us immediately with an error — much better than silently using the wrong string.

The referee function

def rock_paper_scissors(hand1, hand2):
    if hand1 == hand2:
        show_result("Draw!")
    elif hand1 == rock and hand2 == scissors:
        show_result("Player 1 wins!")
    elif hand1 == paper and hand2 == rock:
        show_result("Player 1 wins!")
    elif hand1 == scissors and hand2 == paper:
        show_result("Player 1 wins!")
    else:
        show_result("Player 2 wins!")

rock_paper_scissors(rock, scissors)    # Player 1 wins!
rock_paper_scissors(paper, paper)      # Draw!
rock_paper_scissors(scissors, rock)    # Player 2 wins!

Let's follow Python through rock_paper_scissors(rock, scissors):

  1. Check if hand1 == hand2 — is rock == scissors? That's 0 == 2 — false. Move on.
  2. Check first elif — is hand1 == rock and hand2 == scissors? That's 0 == 0 and 2 == 2 — true! Run show_result("Player 1 wins!") and stop checking.
  3. The remaining elif and else branches are skipped completely — Python found a match and is done.

Phase 3 — Scope: Local vs Global Variables

There is one tricky thing about variables and functions that trips people up almost every time. Let's look at it now, before it catches us out in the calculator.

Scope — Where Does a Variable Live?
📋 Analogy: a shared noticeboard
Imagine a noticeboard on the classroom wall that everyone can see — that's a global variable. Any part of your program can read what's written on it.

But each function also has its own private notepad on its desk — that's a local variable. Anything written on that notepad disappears when the function finishes, and nobody outside the function can see it.

The catch: if a function wants to change what's written on the shared noticeboard (not just read it), it must explicitly say so using the word global.

A broken example — spot the problem

Let's write a Rick-Roll-style function that builds up a famous lyric one phrase at a time. Here is the broken version first: 

lyric = "never gonna "
roll  = ["give you up", "let you down", "run around and desert you",
         "make you cry", "say goodbye", "tell a lie and hurt you"]

def rick(choice):
    lyric = lyric + choice    # ← this does NOT work
    show_result(lyric)

rick(roll[0])

If you run this, Python gives an UnboundLocalError. Here's why: the moment Python sees lyric = ... inside the function, it decides that lyric is a local variable — one that belongs only to this function's private notepad. But the right-hand side of that line tries to read lyric before it has been written to the local notepad. Python is confused, and raises an error.

The fix — global

To tell Python "I want to change the noticeboard — the global variable — not create a local one", add global lyric at the top of the function: 

def rick(choice):
    global lyric              # ← "I want to change the noticeboard"
    lyric = lyric + choice
    show_result(lyric)

rick(roll[0])    # never gonna give you up
rick(roll[1])    # never gonna give you uplet you down

Notice that the second call shows the full accumulated string — because lyric was genuinely changed on the global noticeboard by the first call, and the second call reads the updated version and adds to it again. State builds up across calls — keep that in mind when you're debugging.

In the calculator, all of the state variables you wrote in Session 2 (inputs, selected_input, etc.) are global. Any function that needs to change one of them will need a global declaration. Functions that only read them do not.

🔬 Try It

Phase 4 — Functions Calling Other Functions

So far, every function has been called by you, by typing its name. But functions can also call other functions from inside their own body. This happens all the time in real programs — it's how you break a big job into smaller pieces.

Functions Calling Functions
👨‍🍳 Analogy: a restaurant kitchen
Imagine a head chef who receives a dinner order. The head chef doesn't cook everything themselves — they delegate: "starter chef, make the soup; pastry chef, make the dessert." Each specialist chef does their own job and hands the finished dish back. The head chef just knows who to ask and when.

In Python, the head chef is the outer function. The starter chef and pastry chef are inner functions. The outer function calls the inner functions by name, waits for them to finish, then carries on.

Warm-up — we already did this in Phase 1

You might not have noticed, but you actually saw functions calling functions in Phase 1. Remember the square function you wrote in the challenge? Here is a new function that uses it: 

def show_square(n):
    result = square(n)        # calls square(), which we wrote in Phase 1
    show_result(result)

show_square(5)    # shows 25

When Python reaches square(n) inside show_square, it pauses inside show_square, jumps into square, gets the answer back (25), then returns to show_square and stores that answer in result. Only then does show_result run. Python always finishes the inner function completely before carrying on with the outer one.

for / range() — Doing Something a Set Number of Times
🏃 Analogy: a PE teacher counting press-ups
Imagine a PE teacher shouting "do 5 press-ups — one, two, three, four, five." The teacher doesn't write five separate instructions — they give a single instruction with a repetition count. for i in range(5): does exactly that in Python. The variable i counts up automatically: 0, 1, 2, 3, 4.

Here is the simplest example of a for loop with range(): 

for i in range(3):
    show_result(i)    # shows 0, then 1, then 2

range(3) produces the sequence of numbers 0, 1, 2 (it starts at zero and stops before reaching 3). The variable i takes each value in turn. Everything indented under the for line runs once for each value. You can also use range(len(some_list)) to get an index for every item in a list.

🔬 Try It

What does this display? Think about it before you run it: 

for i in range(5):
    show_result(i * 2)
💡 Hint

i takes the values 0, 1, 2, 3, 4. Multiplied by 2, you get: 0, 2, 4, 6, 8.

The tournament function

Now we can write a tournament function. It plays several rounds of Rock Paper Scissors, calling rock_paper_scissors once for each round. Notice how tournament doesn't contain any Rock Paper Scissors logic itself — it just coordinates. 

player_1_moves = [rock, paper, rock]
player_2_moves = [scissors, rock, rock]

def tournament(p1_moves, p2_moves):
    number_of_rounds = len(p1_moves)
    for i in range(number_of_rounds):
        rock_paper_scissors(p1_moves[i], p2_moves[i])

tournament(player_1_moves, player_2_moves)

Let's follow Python through this call step by step:

  1. number_of_rounds = len(player_1_moves) = 3.
  2. i = 0: calls rock_paper_scissors(rock, scissors) → displays "Player 1 wins!"
  3. i = 1: calls rock_paper_scissors(paper, rock) → displays "Player 1 wins!"
  4. i = 2: calls rock_paper_scissors(rock, rock) → displays "Draw!"

The all-important point: tournament doesn't know or care how Rock Paper Scissors works. All the logic lives in rock_paper_scissors. tournament just picks the right move from the list and passes it along — like the head chef handing an order slip to the right station.

🏆 Phase 4 Challenge — Optional Stretch: Recursive Functions

This is an optional stretch challenge — you don't need it for Session 4. But it's very cool, so have a go if you're up for it!

Here is something remarkable: a function can even call itself. This is called recursion. It sounds impossible — but it works as long as there is a condition that eventually stops the chain.

We'll use factorial as the example. In maths, 5! (read "five factorial") means 5 × 4 × 3 × 2 × 1 = 120. Notice the pattern: 5! = 5 × 4!, and 4! = 4 × 3!, and so on, all the way down to 1! = 1 and 0! = 1. Each step is the same problem, just with a smaller number. That's exactly what recursion does. 

def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)

show_result(factorial(5))    # 120
show_result(factorial(0))    # 1

Let's trace what happens when Python runs factorial(3):

  1. factorial(3) — n is not 0, so return 3 * factorial(2) … pausing here
  2. factorial(2) — n is not 0, so return 2 * factorial(1) … pausing here
  3. factorial(1) — n is not 0, so return 1 * factorial(0) … pausing here
  4. factorial(0) — n is 0, so return 1. Chain stops!
  5. Working back up: 1 × 1 = 1, then 2 × 1 = 2, then 3 × 2 = 6.
The Base Case — The Safety Net
🛡️ Analogy: the ground under a trampoline
Imagine bouncing on a trampoline. Each bounce (each recursive call) is a little smaller. But you need the ground to stop you bouncing forever. In factorial, the base case is if n == 0: return 1. Without it, the function would call itself forever and Python would eventually crash with a RecursionError.

Phase 5 — when_key_pressed and a Working handle_key

It's time to wire everything together. In this phase you will connect a real key-press handler to the calculator so that pressing a key on the Tab5 actually does something. To do that, we need to learn one more idea: passing a function's name as an argument to another function.

Part A — Passing a Function as an Argument

In Phase 4, tournament called rock_paper_scissors by writing its name directly inside its own code. Now we'll see something slightly different: passing a function's name as an argument to another function, so that function can call it for us later.

Passing a Function by Name
📬 Analogy: a delivery driver and an address card
Imagine you hire a delivery driver and hand them a card with your address on it. You're not asking them to deliver anything right now — you're just giving them the instructions they'll need later. When a parcel arrives at the depot, the driver looks at the card and delivers it.

In Python, passing a function name (without ()) is like handing over that address card: you're giving the instructions for what to do later, not running them immediately. The driver (the receiving function) will call your function at the right moment.

In Phase 4, tournament called rock_paper_scissors directly from inside its own code — the name was baked in. Here, we'll tell when_key_pressed which function to call by passing the name as an argument. The imported machinery will then call our function for us, automatically, every single time a key is pressed on the Tab5 — and it will pass in the key that was pressed.

when_key_pressed is a special function we imported from calculator_ui. It is part of the hidden machinery that connects Python to the physical buttons on the Tab5. It takes one argument: the name of a function you have written. Behind the scenes, every time a key is pressed, the Tab5's hardware triggers the imported code, which then calls your function and passes it the key that was pressed. 

when_key_pressed(handle_key)    # no brackets after handle_key!

The brackets (or lack of them) are crucial:

  • With brackets → when_key_pressed(handle_key()) would mean "call handle_key right now, and pass its return value to when_key_pressed". That's wrong — we haven't pressed any key yet, and handle_key doesn't return anything useful.
  • Without brackets → when_key_pressed(handle_key) means "here is the function itself — please call it later, whenever a key is pressed". That's exactly what we want.

🔬 Think About It

💡 Answer

The value would be the string "7" — a single character in double quotes, not the number 7. Keys always arrive as strings. That's why we'll need int(key) later to convert it into a number when we want to do maths with it.

Part B — Writing a Working handle_key

Now let's write a handle_key that actually does something when you press a key — so you can see the whole system working before we add the real calculator maths in Session 4. We'll use the factorial function from the Phase 4 challenge to show a fun result for each digit key.

💡 If you skipped the factorial challenge — click here for the function

No problem! Just type this above your handle_key function: 

def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)
def handle_key(key):
    if key in number_keys and key != ".":
        n = int(key)
        result = factorial(n)
        show_input(str(n) + "! =")
        show_result(result)
    elif key in operator_keys:
        show_input(key)
        show_result("Not implemented yet")
    elif key == "=":
        show_result("Session 4: coming soon!")
    elif key == "C":
        show_input("")
        show_result("0")

Let's walk through each branch:

  • Number key (not "."): we use int(key) to convert the string "7" into the number 7 — we need a real number to pass to factorial. Then we show "7! =" in the top display and the factorial result below. Try pressing 5 — you should see 120. We exclude "." because you can't take the factorial of a decimal.
  • Operator key (+, -, x, /): shows the operator symbol in the top display and "Not implemented yet" below. This will be replaced with real logic in Session 4.
  • "=" key: shows a teaser message — the real equals logic is coming in Session 4!
  • "C" key: clears both displays — a clean slate.

Steps to add this to your program

  1. Make sure factorial is defined above handle_key in your file — Python reads top to bottom, so it must see factorial before handle_key tries to call it.
  2. Type the handle_key function exactly as shown above.
  3. On the next line after the function, add: 
    when_key_pressed(handle_key)
  4. Make sure run() is still the very last line of your file.
  5. Run the program on the Tab5 — press a digit key and watch the display!

📚 What You Learned Today

def / parameters / return
Write a recipe once and call it by name. Pass ingredients in with parameters; get results back with return.
if / elif / else
Decision making: Python checks conditions top to bottom and runs the first branch that is true, ignoring all the rest.
Scope / global
Variables inside a function are local by default — like a private notepad. Use global to change a variable that lives on the shared noticeboard outside.
for / range()
Repeat a block of code a set number of times. range(n) produces the numbers 0 to n−1; the loop variable counts up automatically.
Functions calling functions
A function can call any other function by name. The outer function pauses, the inner function runs fully, then control returns — like a head chef delegating to specialist chefs.
Recursion (optional)
A function can call itself. It always needs a base case — a condition that stops the chain — otherwise Python crashes with a RecursionError.
Functions as arguments
You can pass a function's name (without ()) to another function, which will call it later. This is exactly how when_key_pressed(handle_key) works: you hand over the address card, and the imported machinery delivers the call when a key is pressed.
