Phase 1 — What is a Function?

def — Writing Your Own Recipe
🍰 Analogy: a recipe book
Imagine you write a recipe for chocolate cake. You write it down once, give it a name, and from then on anyone who wants chocolate cake just says "make the chocolate cake recipe". They don't have to re-read all the steps — they just use the name.

In Python, def is how you write the recipe. Typing the function's name with brackets () is how you run it.

Here is the basic shape of a function in Python. Every single part matters, so let's look at each piece: 

def function_name(parameter1, parameter2):
    # everything indented by 4 spaces belongs to the function
    # do some work here
    return result
  • def — tells Python "I am writing a function now".
  • The name — you choose it; use lowercase letters and underscores.
  • Round brackets () — hold the parameters (the ingredients the function needs).
  • The colon : — marks the start of the recipe steps.
  • 4 spaces of indentation — every line that belongs to the function must be indented (shifted right) by 4 spaces. Python uses this to know where the function ends.
  • return — hands a result back to whoever called the function, like passing the finished cake through the serving hatch.

Example 1 — A function that displays something

Let's start simple. This function takes a word and a number, then shows the word that many times on screen. It doesn't need to return anything — it just does a job. 

def repeat_word(word, times):
    show_result(times * word)

repeat_word("hello ", 3)    # shows: hello hello hello
repeat_word("beep ", 5)     # shows: beep beep beep beep beep

Step by step: when Python reaches repeat_word("hello ", 3), it jumps inside the function. word gets the value "hello " and times gets the value 3. Then 3 * "hello " produces the string "hello hello hello ", which show_result puts on screen. Python then comes back out of the function and carries on with the next line.

💡 Hint

Multiplying a string by 0 gives an empty string — nothing shows up. Multiplying by 1 just shows the word once.

Example 2 — A function that returns True or False

This function checks whether a number is even and returns an answer. Before we look at the code, here is a quick maths reminder:

% — The Remainder Operator (Modulo)
🍕 Analogy: sharing slices of pizza
If you have 10 slices and 3 friends, each friend gets 3 slices and you have 1 left over. 10 % 3 gives you that leftover: 1.

If a number is even, dividing it by 2 leaves no remainder — so num % 2 == 0 means "num is even". 
def is_even(num):
    if num % 2 == 0:
        return True
    else:
        return False

show_result(is_even(4))     # True
show_result(is_even(7))     # False

Notice: the if and else are indented 4 spaces (inside the function), and the return lines are indented 8 spaces (inside the if/else block). Python uses those indentation levels to know exactly what belongs where.

🔬 Try It

What does is_even(100) return? What about is_even(1)? Try a few numbers of your own.

💡 Hint

100 % 2 is 0, so is_even(100) returns True. 1 % 2 is 1 (not zero), so is_even(1) returns False.

Example 3 — A function that does arithmetic

Functions are great for maths that you want to repeat without retyping. This one converts a temperature from Celsius to Fahrenheit. 

def celsius_to_fahrenheit(temp):
    result = temp * 9 / 5 + 32
    return result

show_result(celsius_to_fahrenheit(0))     # 32.0  — freezing point
show_result(celsius_to_fahrenheit(100))   # 212.0 — boiling point

The function stores the answer in a local variable called result, then hands it back with return. show_result receives that value and displays it. (We'll learn much more about local variables in Phase 3.)

🔬 Try It

Try celsius_to_fahrenheit(37) — that's body temperature. What do you expect? Try celsius_to_fahrenheit(-40) — this one has a famous answer!

💡 Hint

Body temperature comes out as 98.6°F. At -40 the two scales meet — the answer is also -40!

Phase 2 — Functions that Make Decisions: Rock Paper Scissors

Functions become really powerful when they can look at their inputs and take different actions depending on what they find. We already saw a tiny bit of this with is_even — now let's build something bigger: a Rock Paper Scissors referee.

if / elif / else — Signposts at a Junction
🛣️ Analogy: signposts at a road junction
Imagine arriving at a crossroads with several signposts. You read the first one — if it matches where you're going, you take that road and ignore all the others. If not, you move on to the next sign. if is the first signpost. elif (short for "else if") is every sign after that. else is the last sign that says "take this road if none of the others matched". Python reads them top to bottom and stops as soon as it finds one that is true.

Setting up the hand values

Instead of typing the strings "rock", "paper", and "scissors" everywhere (and risking a typo), we give each hand a number: 

rock     = 0
paper    = 1
scissors = 2

Now whenever we want to say "rock", we just write the variable name rock. Python can compare numbers quickly with ==, and if we ever mistype the variable name Python will tell us immediately with an error — much better than silently using the wrong string.

The referee function

def rock_paper_scissors(hand1, hand2):
    if hand1 == hand2:
        show_result("Draw!")
    elif hand1 == rock and hand2 == scissors:
        show_result("Player 1 wins!")
    elif hand1 == paper and hand2 == rock:
        show_result("Player 1 wins!")
    elif hand1 == scissors and hand2 == paper:
        show_result("Player 1 wins!")
    else:
        show_result("Player 2 wins!")

rock_paper_scissors(rock, scissors)    # Player 1 wins!
rock_paper_scissors(paper, paper)      # Draw!
rock_paper_scissors(scissors, rock)    # Player 2 wins!

Let's follow Python through rock_paper_scissors(rock, scissors):

  1. Check if hand1 == hand2 — is rock == scissors? That's 0 == 2 — false. Move on.
  2. Check first elif — is hand1 == rock and hand2 == scissors? That's 0 == 0 and 2 == 2 — true! Run show_result("Player 1 wins!") and stop checking.
  3. The remaining elif and else branches are skipped completely — Python found a match and is done.

Phase 3 — Scope: Local vs Global Variables

There is one tricky thing about variables and functions that trips people up almost every time. Let's look at it now, before it catches us out in the calculator.

Scope — Where Does a Variable Live?
📋 Analogy: a shared noticeboard
Imagine a noticeboard on the classroom wall that everyone can see — that's a global variable. Any part of your program can read what's written on it.

But each function also has its own private notepad on its desk — that's a local variable. Anything written on that notepad disappears when the function finishes, and nobody outside the function can see it.

The catch: if a function wants to change what's written on the shared noticeboard (not just read it), it must explicitly say so using the word global.

A broken example — spot the problem

Let's write a Rick-Roll-style function that builds up a famous lyric one phrase at a time. Here is the broken version first: 

lyric = "never gonna "
roll  = ["give you up", "let you down", "run around and desert you",
         "make you cry", "say goodbye", "tell a lie and hurt you"]

def rick(choice):
    lyric = lyric + choice    # ← this does NOT work
    show_result(lyric)

rick(roll[0])

If you run this, Python gives an UnboundLocalError. Here's why: the moment Python sees lyric = ... inside the function, it decides that lyric is a local variable — one that belongs only to this function's private notepad. But the right-hand side of that line tries to read lyric before it has been written to the local notepad. Python is confused, and raises an error.

The fix — global

To tell Python "I want to change the noticeboard — the global variable — not create a local one", add global lyric at the top of the function: 

def rick(choice):
    global lyric              # ← "I want to change the noticeboard"
    lyric = lyric + choice
    show_result(lyric)

rick(roll[0])    # never gonna give you up
rick(roll[1])    # never gonna give you uplet you down

Notice that the second call shows the full accumulated string — because lyric was genuinely changed on the global noticeboard by the first call, and the second call reads the updated version and adds to it again. State builds up across calls — keep that in mind when you're debugging.

In the calculator, all of the state variables you wrote in Session 2 (current_input, first_number, etc.) are global. Any function that needs to change one of them will need a global declaration. Functions that only read them do not.

🔬 Try It

💡 Hint — which error message should I see?

You should see something like: UnboundLocalError: local variable 'lyric' referenced before assignment. This is Python's way of saying "you're trying to read from the local notepad before writing anything there".

Phase 4 — Connecting handle_key to the Calculator

Now you have all the tools. Let's use them in the calculator. In Session 2 you set up all the state variables and lists — now we add the function that tells the calculator what to do when each key is pressed.

handle_key — The Calculator's Traffic Controller
🚦 Analogy: a traffic controller at a busy junction
Every time a driver (a key press) arrives, the controller checks which lane they belong to and sends them the right way. The controller doesn't do the driving — it just decides who goes where. handle_key is exactly that: it checks which key was pressed and calls the right helper function.

Writing handle_key

This function uses exactly what you practiced in Phase 2 — an if / elif chain that checks the key one condition at a time. There is nothing new here conceptually; it's just applying the same skill in the calculator context.

  1. After your variable and list declarations (but before run()), type the function below. Watch your indentation! 
def handle_key(key):
    if key in number_keys:
        add_digit(key)
    elif key in operator_keys:
        press_operator(key)
    elif key == "=":
        press_equals()
    elif key == "C":
        press_clear()
    elif key == "DEL":
        press_delete()
    elif key == "+/-":
        press_negate()

Let's read each branch:

  • if key in number_keys — the pressed key is a digit or a decimal point, so call add_digit.
  • elif key in operator_keys — it's +, -, x, or /, so call press_operator.
  • elif key == "=" — the equals key, so call press_equals.
  • elif key == "C" — the clear key, so call press_clear.
  • elif key == "DEL" — the delete key, so call press_delete.
  • elif key == "+/-" — the positive/negative toggle, so call press_negate.

Notice that key in number_keys uses the same in keyword you used in Session 2 to check if something is inside a list. You already know this trick — now it's doing real work!

Each branch calls a helper function — add_digit, press_operator, and so on. Those helper functions don't exist yet. We'll write them in Session 4. For now, handle_key is a skeleton: the structure is there, but the rooms are empty.

when_key_pressed — The Doorbell
🔔 Analogy: a doorbell
You don't stand by your front door all day listening for a knock. Instead, you wire up a doorbell — so whenever someone presses it, your phone buzzes and you know to answer. when_key_pressed is that wiring. You give it the name of your function (handle_key) and from then on, every time the player presses a key on the calculator, Python automatically calls handle_key with that key.

Registering the doorbell

After the handle_key function, and before run(), add this single line: 

when_key_pressed(handle_key)

Look carefully: there are no brackets after handle_key. Why not? Because you are passing the recipe itself to when_key_pressed, not running it right now. If you wrote when_key_pressed(handle_key()) with brackets, Python would try to run handle_key immediately — before any key is pressed — which is not what you want.

⚠️ Expected behaviour when you run it now

If you run the program at the end of this session and press a key, you will see an error message about add_digit or press_operator not being defined. That is completely fine and expected. The helper functions don't exist yet — we write them in Session 4. The important thing to check now is that the program starts up without errors and shows "Hello!" on screen.

Steps to type today

  1. Open your Session 2 file (the one ending with run()).
  2. On the line before run(), add the handle_key function exactly as shown above.
  3. On the line after the handle_key function (still before run()), add: 
    when_key_pressed(handle_key)
  4. Make sure run() is still the very last line.
  5. Run the program — you should see "Hello!" and no crash on start-up.
💡 Hint — indentation trouble?

Every line inside handle_key must start with exactly 4 spaces. The if line has 4 spaces; the add_digit(key) line below it has 8 spaces (4 for being inside the function, plus 4 for being inside the if). All the elif lines also have 4 spaces.

💡 Hint — where exactly does when_key_pressed go?

It should come after the closing line of handle_key and before run(). Both when_key_pressed(handle_key) and run() should have no indentation (they are at the left edge of the file, not inside any function).

🌟 What You Learned Today

def
Writes a named function once — a recipe you can run whenever you need it by typing its name with ().
Parameters
Variables listed in the brackets after the function name. They receive values ("ingredients") when the function is called.
return
Hands a result back to whoever called the function. Once Python hits return, it exits the function immediately.
if / elif / else
Lets a function make decisions. Python reads the conditions one at a time from top to bottom and runs only the first branch that is true.
Scope — local vs global
Variables created inside a function are local — private to that function. To change a variable that lives outside the function, declare it with global first.
when_key_pressed
A "doorbell" that registers your function. Every time a key is pressed on the calculator, Python automatically calls the function you registered — passing in the key that was pressed.
