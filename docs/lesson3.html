Session 3: Making it Calculate

This is the big session — you'll write the four functions that make the calculator actually do maths. By the end, you'll be able to type a sum and see the answer!

📌 New idea: global
Think of a shared noticeboard on the classroom wall. Anyone can read it, but to change what's written on it, you have to walk up to the board. In Python, variables like current_input live on the "noticeboard" (outside any function). If a function wants to change one of them, it must first say global current_input — that's like saying "I'm going to walk up and change the noticeboard".

You'll see global at the top of most functions this session. If you forget it, Python thinks you're making a new local variable instead of changing the shared one.

🔢 New idea: float()
Imagine a label stuck to a jar that says "12". The label looks like a number, but you can't do maths with a label. float("12") pulls off the label and gives you a real number: 12.0.

current_input is always stored as a string (text) because it's built up character by character. Before we can do arithmetic we must convert it: float(current_input).

Function 1: add_digit

This runs every time the user taps a digit or the decimal point. It adds the character to current_input and updates the screen.

def add_digit(key):
    global current_input, start_new_number
    if start_new_number:
        current_input    = ""
        start_new_number = False
    if key == "." and "." in current_input:
        return
    current_input = current_input + key
    show_input(current_input)
  • If start_new_number is True, we wipe the display clean first (the previous answer is no longer needed).
  • The line if key == "." and "." in current_input: return stops you adding two decimal points to the same number.
  • current_input = current_input + key adds the new character to the end of what's already there.
🚩 Understanding the start_new_number flag
Think of it like a "fresh page" sticky note. Most of the time it's False — we just keep adding digits. When an operator or equals is pressed, we stick the note on: True. The very next digit press sees the note, tears off the old content, and starts fresh.

Function 2: press_operator

This runs when +, −, x, or / is tapped. It saves the first number and remembers which operator was chosen.

def press_operator(key):
    global first_number, operator, start_new_number
    if current_input != "":
        first_number = float(current_input)
    operator         = key
    start_new_number = True
    show_input(current_input + " " + operator)
  • We only update first_number if the user has actually typed something.
  • We store the operator key (e.g. "+") so calculate() knows what maths to do.
  • Setting start_new_number = True means the next digit press will start a fresh number.

Function 3: calculate

This is the heart of the program. It looks at operator and does the right maths, then returns the answer.

↩️ New idea: returning a value
Think of asking a friend a question. You say "what is 3 + 5?" and they hand you back the answer: 8. return result is Python's way of handing back an answer to whoever called the function. return on its own (with no value) means "stop here and go back — something went wrong". 
def calculate():
    second_number = float(current_input)
    if operator == "+":
        result = first_number + second_number
    elif operator == "-":
        result = first_number - second_number
    elif operator == "x":
        result = first_number * second_number
    elif operator == "/":
        if second_number == 0:
            return "Error"
        result = first_number / second_number
    else:
        result = second_number
    return result
  • Each elif branch handles one operator. Only one branch runs — Python stops checking once it finds a match.
  • Division by zero would crash the program, so we check for it and return "Error" instead.
  • The final return result hands the answer back to press_equals.

Function 4: press_equals

This glues everything together. It calls calculate(), shows the result, and resets the state ready for the next sum.

def press_equals():
    global current_input, first_number, operator, start_new_number
    if operator == "" or current_input == "":
        return
    answer = calculate()
    if answer == "Error":
        show_input("")
        show_result("Error!")
        current_input    = ""
        operator         = ""
        start_new_number = False
        return
    if answer == int(answer):
        answer = int(answer)
    show_input("")
    show_result(answer)
    current_input    = str(answer)
    first_number     = 0
    operator         = ""
    start_new_number = True
  • The first if checks that there is something to calculate — if not, return exits early.
  • if answer == int(answer) removes the .0 from whole numbers so 10.0 shows as 10.
  • After showing the result, we store it back into current_input so the user can chain calculations.

Where to put these functions

Add all four functions above handle_key in your file — Python must read a function's definition before handle_key can call it.

Step by step

  1. Find the line def handle_key(key): in your program.
  2. Type the add_digit function above it.
  3. Type the press_operator function below add_digit.
  4. Type the calculate function next.
  5. Type the press_equals function after calculate.
  6. Press Run.
  7. Tap: 1, 2, +, 5, =. You should see 17!
